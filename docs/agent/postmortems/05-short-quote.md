# 复盘：原话校验可被很短的 quote 绕过（#5）

## 怎么发现的

原话校验是防编造设计的确定性那一半：模型可以改写 `statement`/`value`，但 `quote` 必须是患者的原话。审查时用反例试了一下，发现只要 quote 是患者话里的任意子串就能通过：

- 患者说「晚上有点热」，模型写「高热39℃」，quote 填「热」——通过。
- quote 和结论毫不相干（「晚上有点」支撑「黄痰」）——通过。
- 患者说「没有喘不上气」，模型写「活动后气喘」，quote 填「喘不上气」——通过，否认被翻成了阳性。
- src 把各轮患者的话拼起来再去掉标点，上一轮结尾「胸口」加下一轮开头「痛得厉害」，能拼出一句没人说过的「胸口痛得」——通过。

backend 的问题更大：它只拿最新一轮回答做比对，而回答往往很短，单字 quote 很容易命中。

## 为什么会发生

两边复制了同一段检查：

```ts
const needle = normalize(quote);
if (!needle || !haystack.includes(needle)) reject();
```

它只回答了「这几个字患者说过吗」，没回答「这几个字能支撑这条结论吗」。具体有四个漏洞：

- 没有长度下限；
- 不看 quote 和结论有没有关系；
- 不看 quote 前面是不是否认；
- src 拼接各轮后，轮次边界没了。

测试只测了「编造的 quote 被丢弃」，没测「真实但无意义的 quote」。

## 怎么修的

新增共享模块 `shared/safety/grounding.ts`，`normalize` 也挪到这里。`groundFacts`（src）和 `applyUpdates`（backend）都改用它。出现下面任一种情况，quote 就被拒绝，照旧进入 `dropped` / `rejected`：

1. **太短**：去掉标点后不到 3 个字。例外是 quote 恰好是患者一整轮的回答，所以「有」「没有」「三天」这种短答仍然有效。
2. **和结论无关**：去掉「了、的、有、是、我」这些常用字后，quote 和 `statement`/`value` 没有任何共同的汉字或字母数字。同样适用整轮例外；结论为空时（backend 没给 value）跳过这一项。
3. **被否认**：quote 前面紧挨着否定词（判断方法和 #4 的否定判断相同：同一分句、先屏蔽不表示否定的词），而结论本身不带否定。
4. **跨轮**：逐轮比对，任何一轮单独能找到才算。src 不再拼接各轮。

设计说明：计划里写的是 `isGroundedQuote(quote, haystack, claim, { wholeTurn? })`。实现时把 haystack 改成「各轮文字的数组」，「quote 是否等于整轮」由函数自己算，不需要调用方传开关。这样 src（多轮）和 backend（最新一轮）用同一个接口，例外条件也不会被调用方传错。

## 怎么防止再犯

- 只有一份检查代码，两个 agent 共用。
- `tests/grounding.test.ts` 同时测两个方向：
  - 该拒的：单字、无关、被否认、跨轮拼接，四种都必须被拒；
  - 该留的：整轮短答、带否定的结论，都必须保留，防止以后收紧规则时误杀正常回答。
- 评测里一直记录被丢弃的 quote 数量（`droppedFacts` / `rejected`）。规则收得太紧会直接体现在这个数字上。

## 对已有结果的影响

- `npx tsx scripts/eval-agent.ts --mock`：通过率 6/6 不变，三个条件的分数和修复前完全一致（C 85.7）。
- 被丢弃的事实：6 个病例共 27 条里，只多丢了 1 条，是 ortho-001 里患者答的「会的」。2 个字、又不是整轮回答，单独拿出来什么也证明不了，丢掉是对的。
- backend 的完整问诊测试全部通过（16/16）。
- 真实模型的通过率：**待运行，需要密钥**。重点要看 `droppedFacts` 有没有明显上升。真实模型改写得更多，「和结论无关」这一条可能误杀同义改写（比如 quote「心口堵得慌」对应 statement「胸闷」）。如果误杀多，再考虑用同义词表放宽。
