# 复盘：危险信号规则的否定词判断导致漏报（#4）

## 怎么发现的

建 #8 的危险信号测试集时，按 issue 列出的易误判说法写了用例，再跑 `scripts/eval-red-flags.ts --rules` 拿基线。38 条危险信号里：

- src 漏 15 条（召回 58.3%），backend 漏 11 条（召回 64.5%）。
- 平铺直叙的说法全中，漏报全在三类：不表示否定的组合词（不时、不停、无缘无故……）、转折句、多轮对话。
- 反过来，「否认有明显的呼吸困难」被当成了危险信号（明确否认误报 1/19）。

## 为什么会发生

两边复制了同一段代码：

```ts
const NEGATION = /(没有|没|无|不|否认|未)[^，。,.!！?？]{0,3}$/;
const before = text.slice(index - 6, index);
if (NEGATION.test(before)) continue;
```

意思是：症状前 6 个字里，只要最后 4 个字以内出现「不/无/没」中的任何一个字，就当作否认。它有四个问题：

1. **只看字，不看词。** 「不时」「不停」「无缘无故」「全身无力」「是不是」里都有否定字，但都不是否认。危险信号的说法里恰好常有这些词（一直不停抽搐、止不住地吐血），所以漏报正落在最该报的地方。
2. **不看句子结构。** 「没有发烧但呼吸困难」里，「没有」否认的是发烧，可它离呼吸困难只有 4 个字，就被算成了否认。
3. **把各轮拼起来匹配。** 两个图都把患者各轮用 `\n` 拼成一段再匹配，而 `\n` 不在排除的字符里。上一轮答「没」，下一轮说「喘不上气」，「没」就把下一轮否认掉了。
4. **窗口是固定 3 个字。** 「否认有明显的」中间隔了 4 个字，没被认出是否认。所以同一个窗口同时造成了漏报和误报。

根本原因是只靠字符窗口判断否定，又没有带易混用例的测试集：已有测试只覆盖了「没有呼吸困难」这一种否认，从来没测过「不时呼吸困难」。

## 怎么修的

新增共享模块 `shared/safety/red-flags.ts`，两个 agent 都从这里引用（各自的规则表不动，规则表合并是 #13）：

1. **只看命中所在的分句。** 遇到标点、换行或转折词（但/但是/可是/不过/却）就断句，只检查命中位置之前、同一分句里的文字。
2. **先屏蔽不表示否定的组合词。** 不时、不停、不断、不止、止不住、不知不觉、不知道、无缘无故、毫无征兆、无力、没完没了、是不是、不舒服、受不了，都替换成等长的占位符，位置不变。
3. **否定词必须紧挨着症状。** 中间只允许出现固定列表里的补充词（有、出现、感到、觉得、明显的、什么），最多 3 个。所以「否认有明显的呼吸困难」算否认，「不时呼吸困难」不算。
4. **每轮患者的话单独匹配。** `matchPatientTurns()` 逐轮匹配再合并，两个图的分级节点都改用它。

## 怎么防止再犯

- **测试数据驱动。** `tests/red-flags.test.ts` 直接读 `evals/red-flags/cases.json`，对两套实现分别断言：规则覆盖到的危险信号必须命中期望规则，明确否认和普通主诉一律不触发。以后发现新的误判说法，往 JSON 里加一条就同时进了测试和评测。
- **只有一份代码。** 否定判断不再复制两份，修一处两边都生效。
- **评测脚本持续跑。** 每次改规则都跑 `eval-red-flags.ts --rules`，看召回和误报。

## 已知局限

- **覆盖缺口不归这个 issue。** 规则表没有的症状照样报不出来（backend 没有晕倒、昏过去的规则；src 没有叫不醒、停止呼吸），留给 #13 合并规则表。
- **否认出现在命中之后，还是会误报。** 否定只检查命中位置之前，所以像「胸口痛，没有出汗」这种句子，规则从「胸口痛」开始一直匹配到「出汗」，后面的「没有」管不到，「胸痛伴大汗」照样触发。规则只能把等级往上调，这类误报的代价是多送一次急诊，不会漏报，所以这次不处理，也没有放进测试集。
- **屏蔽词和补充词都是固定列表。** 遇到列表外的说法（比如「未见」），还是会判错。
