# 3 分钟讲解稿

> 配合 `/agent` 页面演示。括号里是操作。

## 0:00 问题（30 秒）

这个项目原来的问诊功能是：用户把整段医患对话手动敲进去，模型一次性生成病历。它有两个问题。第一，真实场景里没人会把对话整理好再给你，信息要靠问出来。第二，模型一次写完就交付，没人检查它有没有编造。

我顺手还修了两个现成的 bug：对比页用的是 AI SDK v4 的流格式，升级到 v6 之后回答其实一直是空的；评分接口解析失败时会静默返回一组 70 多分的默认分。两个 bug 加在一起，对比页的分数一直是假的。

## 0:30 方案（60 秒）

（打开 `/agent`，点「胸闷心悸两周」，点「自动跑完整场问诊」）

我用 LangGraph 搭了一个问诊 agent。它只拿到一句主诉，剩下的要自己问。

右边是图的执行轨迹，每个节点做了什么都实时推出来：
- **intake** 从对话里提事实。每条事实都必须附上患者的原话，找不到原话就丢掉。这是代码检查，不靠模型自觉。
- **red_flag** 判断危险信号。这个病例是活动后胸闷，被判成「尽快就诊」。如果是持续胸痛加大汗，就直接出急诊提示，跳过诊断。这条边是硬编码的，不让模型商量。
- 信息不够就 **ask** 追问，最多 4 轮。
- **diagnose → care_plan → self_check**：自查不通过，会带着具体问题打回去重写，最多两次。
- 最后的病历由代码渲染，不是模型写的，所以每个诊断后面都有事实编号，底下列着患者原话。

## 1:30 为什么是 LangGraph（40 秒）

三个框架我都写了 demo。LangChain 是零件：我用它的 `withStructuredOutput` 做结构化输出，并通过 AI Gateway 调模型。LangGraph 是流程：追问环、自查环、急诊短路，这些都需要**确定地**执行，而且要能一步步展示出来。

CrewAI 我也用同样的任务做了一版：医生 agent 通过 CrewAI 的委派工具向患者 agent 提问，再交给审核 agent。写起来快很多，但问几次、什么时候停、审核能不能真的拦住编造，都在框架和模型手里。医疗场景我更想要可控。

还有一个部署层面的原因：CrewAI 只有 Python 版，LangGraph.js 可以直接跑在 Next.js 的 API route 里，上 Vercel 零改造。

## 2:10 工程细节（30 秒）

- Vercel 函数是无状态的，所以我没用 LangGraph 的 checkpointer。每次请求带完整对话，图重新推一遍。同一张图在评测里切成 simulated 模式，模拟患者在图里回答，形成闭环。
- 所有循环都有上限，最坏情况下的调用次数是能算出来的。
- 17 个测试，包括起一个本地假 OpenAI 服务器，验证 LangChain 真实请求的格式。

## 2:40 评估与取舍（20 秒）

评测脚本比较三种情况：完整对话一次调用、只给主诉一次调用、agent 自己问。裁判都是同一个。预期是 agent 明显好于「只给主诉」，接近「完整对话」，代价是模型调用次数多了 10 倍左右。这个取舍值不值，取决于场景：问诊准确性比成本重要。

## 可能被追问

- **为什么不用 tool-calling agent（ReAct）让模型自己决定调什么？** 问诊的步骤是固定的，真正需要模型判断的是每一步的内容，不是步骤顺序。把顺序交给模型，多了不确定性，没换来什么。
- **怎么防编造？** 两层：事实必须能在原话里找到（代码检查），诊断必须引用事实编号（代码检查）；另外 self_check 用模型质控。最终文字由代码渲染。
- **规则和模型冲突怎么办？** 风险等级取两者的最大值，规则只升不降。
- **模拟患者会不会作弊，说出诊断？** prompt 禁止说诊断名，只能按病例原对话回答。每次评测的完整问诊记录都存在 JSON 里，可以抽查。
- **成本？** 一次完整问诊大约 10-15 次调用。可以把 intake 换成小模型、diagnose 用大模型，按节点选模型。
- **还能做什么？** 用持久化 checkpointer 支持长会话；接真实检查结果做第二轮问诊；在 self_check 里加药物相互作用库。
