# 3 分钟讲解稿

> 配合 `/agent` 页面演示。括号里是操作。

## 0:00 问题（30 秒）

这个项目原来的问诊功能是：用户把整段医患对话手动敲进去，模型一次性生成病历。它有两个问题。第一，真实场景里没人会把对话整理好再给你，信息要靠问出来。第二，模型一次写完就交付，没人检查它有没有编造。

我把它改成了预问诊：患者见医生之前，Agent 负责问清楚病史、发现危险信号，最后给医生一份病历草稿。Agent 不下诊断。

## 0:30 方案（60 秒）

（打开 `/agent`，点「胸闷心悸两周」，点「自动跑完整场问诊」）

右边是记录表和每次请求经过的图节点：
- **screen**：每一轮先用规则查危险信号。持续胸痛加大汗这种Ⅰ、Ⅱ级情况，直接提示急诊，一次模型都不调用。规则会识别「没有胸痛」这种否认。
- **understand**：模型从患者这一次的回答里抽取要点，填进记录表。每条都必须附上患者原话，对不上原话的直接丢掉，这是代码检查。
- **triage** 和 **phrase** 并行：一个判断危险等级，一个把下一轮的问题改写成口语。问什么不是模型决定的，是规划器按模板选的：先问危险信号，再问必填项，每轮两个，最多四轮。
- 问完以后 **retrieve** 检索诊疗指南，**draft** 写病历，**check** 自查。给医生的每条建议都必须引用检索到的指南片段，没有出处会被打回重写，最多两次。

（等病历出来，指给听众看「依据：《…》」）

## 1:30 为什么这样设计（40 秒）

问诊的步骤是固定的，需要模型判断的是每一步的内容，不是步骤顺序。所以我用 LangGraph 把流程写成代码：追问环、自查环、急诊短路都有上限，最坏情况下一次问诊调用 20 次模型，是能算出来的。

CrewAI 我也用同样的任务做了一版，写起来快，但问几次、什么时候停、审核能不能真的拦住编造，都在框架和模型手里。医疗场景我更想要可控。

## 2:10 工程细节（30 秒）

- 问诊状态用 LangGraph 的 checkpointer 保存，`interrupt()` 暂停等患者回答，可以换个进程接着问。部署时换成 PostgreSQL，锁和限流放 Redis，实例本身无状态，能横向扩展。
- 同一问诊的两个回答同时到达，只执行一个，另一个返回 409。浏览器中途关掉，后端会中止这次运行，不再继续调用模型。
- 模型调用失败不会假装成功：问诊标成失败，可以从失败的那一步重试。
- `npm test` 共 85 个测试，全部离线；另有 5 个对真实 PostgreSQL 和 Redis 的集成测试。

## 2:40 评估与取舍（20 秒）

真实 Bedrock 评测（6 个病例 × 3 次，模拟患者和裁判用另外两个模型家族）：病历完整性 92.5、准确性 92.2，指南引用准确率约 86%，一次问诊约 $0.15、60 秒。危险信号上，模型单独只识别 68%，加上规则是 100%，否认零误判。规则前置把每轮追问从 4.7 秒降到 3.5 秒。真实评测还找出了几处规则把否认误判成急诊的问题，原话都进了测试集。

## 可能被追问

- **为什么不用 ReAct agent 让模型自己决定调什么？** 步骤顺序固定，交给模型只会多出不确定性。真正需要模型的是抽取、分级、改写和写作。
- **怎么防编造？** 记录表只接受能对上患者原话的内容（代码检查）；病历每句话要引用记录表要点；给医生的建议要引用指南片段；最后再用模型自查。
- **规则和模型冲突怎么办？** 取更紧急的等级，规则只升不降。
- **为什么不下诊断？** 预问诊的定位是帮医生收集病史。可能原因只作参考，而且必须有指南出处。
- **成本？** 每轮追问只用快档模型；写病历和自查才用慢档。估算一次问诊约 $0.02（`scripts/bench-latency.ts`，模拟计时），真实数字待补跑。
- **原来的 Next.js 版呢？** 那是早期原型，会下鉴别诊断，已经移到 `experiments/next-agent/`，只用来复现当时的评测。现在只有 `backend/` 一套实现，危险信号规则和原话校验也只有一份。
