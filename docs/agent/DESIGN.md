# 预问诊 Agent 设计文档

本文是 `backend/` 的设计说明，代码注释里的「DESIGN.md §x」都指向这里。只保留代码实际用到的章节，编号沿用最初的设计稿，所以不连续。每节最后一行写明对应的代码。

## §3 危险分级

### §3.3 四级分诊

采用急诊预检分诊的四级标准（《急诊预检分诊专家共识》）：

| 等级 | 名称 | 含义 | Agent 的处理 |
|---|---|---|---|
| Ⅰ | 濒危 | 正在或即将发生生命威胁 | 立即停止问诊，提示急诊或拨打 120 |
| Ⅱ | 危重 | 病情危重或迅速恶化 | 同上 |
| Ⅲ | 急症 | 有潜在生命威胁，需尽快就诊 | 继续问诊，病历里标注 |
| Ⅳ | 非急症 | 没有急性发作的危险表现 | 继续问诊 |

等级由两部分决定，取更紧急的那个：

1. **规则**：对患者原话做正则匹配，处理否认（「没有胸痛」不触发）。规则表只有一张，在 `shared/safety/red-flags.ts`。规则只能把等级调高，不能调低。
2. **模型**：快档模型按上表判断，拿不准时要求选更紧急的等级。

每一轮先跑规则（`screen` 节点）。规则命中Ⅰ、Ⅱ级时直接进急诊，不调用模型。

代码：`shared/safety/red-flags.ts`、`backend/src/triage.ts`、`backend/src/graph.ts` 的 `screen` 和 `triage`。

## §6 问诊流程

```
setup → screen ─┬─ 规则命中Ⅰ/Ⅱ级 → emergency
          ▲     └─ understand ─┬─ triage ─┬─ Ⅰ/Ⅱ级 → emergency
          │                    └─ phrase  ├─ 还有要问的 → ask → wait ┐
          └───────────────────────────────┼──────────────────────────┘（患者回答）
                                          └─ 问完了 → retrieve → draft → check ─┬─ 通过 → finalize
                                                                     ▲          │
                                                                     └─ 不通过（≤2 次）
```

- 流程由代码决定（LangGraph 的条件边），模型只负责每一步里的一项小任务：从回答中抽取要点、判断等级、改写问题、写病历、自查。
- 所有循环都有上限：追问最多 4 轮（§7.4），自查不通过最多重写 2 次。
- 默认直接用模板问法。`AGENT_PHRASING=model` 时 `phrase` 用快档模型改写问题，与 `triage` 并行；改写好的问题只在问诊继续时使用，判为急诊时丢弃。真实 Bedrock 上两种问法的病历质量相同，所以默认用模板。

代码：`backend/src/graph.ts`。

## §7 问诊模板与记录表

### §7.1 模板

每次问诊都问通用要点（起病时间、性质、诱因、缓解因素、伴随症状、既往史、用药、过敏史），再加上与主诉匹配的专科模板：胸痛/胸闷/心悸、腹痛/腹泻/恶心、头痛/头晕、咳嗽/发热。每个要点有四种类型，决定提问顺序：

| 类型 | 含义 |
|---|---|
| `redflag` | 危险信号筛查，最先问 |
| `required` | 病历必须有的内容 |
| `discriminating` | 能区分可能原因的问题 |
| `optional` | 补充细节 |

代码：`backend/src/templates.ts`。

### §7.2 记录表

记录表是 Agent 的记忆：每个要点一行，状态为「未问」「已回答」「不清楚」。已回答的要点保存规范用语和**患者原话**。模型提出的更新只有通过原话校验才写入（`shared/safety/grounding.ts`）：原话必须逐字出现在患者这一次的回答里，长度至少 3 个字（整句回答除外），与结论有共同的字，并且不是患者否认的内容。「不清楚」不会覆盖已有的回答。

代码：`backend/src/record.ts`、`shared/safety/grounding.ts`。

### §7.3 选题规则

下一轮问什么由代码决定，不由模型决定：

1. 只从「从没问过、仍未问」的要点里选；
2. 按 `redflag → required → discriminating → optional` 排序；
3. 每轮最多 2 个问题；
4. 与已问过的问题相似度（字的二元组 Jaccard）≥ 0.6 的跳过。

代码：`backend/src/planner.ts` 的 `plan`。

### §7.4 停止条件

满足任一条件就停止追问、开始写病历：

- 危险信号筛查项和必填项都有了结果，鉴别要点也都问过；
- 已经问满 4 轮（`DEFAULT_MAX_ROUNDS`）。

最坏情况下一次问诊的模型调用次数：开场 3 次（抽取、分级、改写），第 1～3 次回答各 3 次，第 4 次回答 2 次（问满了，不再改写），写病历和自查最多各 3 次，合计 3 + 9 + 2 + 6 = 20 次。规则命中Ⅰ、Ⅱ级时为 0 次。

代码：`backend/src/planner.ts`。

## §8 会话记忆

`wait` 节点调用 LangGraph 的 `interrupt()` 暂停，整个状态（记录表、已问过的问题、对话）由 checkpointer 按问诊编号保存：单机是 SQLite，部署是 PostgreSQL。患者的下一次回答从断点恢复，可以换进程甚至换机器，状态不需要从对话重新推导。`ask` 和 `wait` 分成两个节点，恢复时就不会重跑生成问题的模型调用。

防重复追问有三层：选题时跳过已问过的要点（§7.3 第 1 条）、跳过已有结果的要点、跳过措辞相似的问题。

代码：`backend/src/graph.ts` 的 `wait`，`backend/src/service.ts`。

### §8.2 只看最新一轮回答

`understand` 节点每次只把患者**最新一轮**回答和当前记录表交给模型，只更新这次问到的要点，以及患者顺带提到的未问要点。旧的回答不会被重新解读，记录表不会因为模型重读历史而漂移。

代码：`backend/src/graph.ts` 的 `understand`，`backend/src/prompts.ts` 的 `extractPrompt`。

## §9 接口与安全

- 除 `/healthz`、`/readyz` 和演示页面外，接口都要求 `Authorization: Bearer <接口密钥>`。程序只保存密钥的哈希值，用恒定时间比较。
- 问诊只对创建它的密钥可见，其他密钥一律 404。
- 同一问诊同时只处理一个回答或重试，后到的请求返回 409；处理期间查询状态为「running」。
- 客户端断开时中止运行，并取消正在进行的模型调用；问诊标为失败，可以重试。
- 请求体不超过 8KB，单次输入不超过 500 字。
- 日志不记录患者说的内容。
- 模型调用失败返回 502，问诊保存为「失败」，可以用 `/retry` 从失败的那一步继续。

Next.js 的 `/api/agent` 只做转发：后端的接口密钥留在服务端；可以按 IP 限流（`AGENT_RATE_LIMIT_PER_MINUTE`，默认关闭）；浏览器断开时转发请求随之中止，后端也就停下来。

代码：`backend/src/server.ts`、`backend/src/security.ts`、`backend/src/lock.ts`、`src/app/api/agent/route.ts`、`src/lib/rate-limit.ts`。

## §12 成本控制

### §12.4 快、慢两档模型

| 任务 | 档位 | 默认模型 |
|---|---|---|
| 抽取要点（extract）、危险分级（triage）、改写问题（phrase） | 快档 | Claude Haiku 4.5 |
| 写病历（note）、自查（review） | 慢档 | Claude Sonnet 4.6 |

每轮追问只用快档；慢档只在结束时用 1～3 次。默认模型的选择见 `backend/README.md` 的「默认模型」。

代码：`backend/src/llm.ts` 的 `TASK_TIER`。

### §12.7 每个密钥的限额

每个接口密钥每分钟最多 `RATE_LIMIT_PER_MINUTE` 次请求（默认 30），每天最多新建 `DAILY_CONSULTATION_LIMIT` 次问诊（默认 200）。部署多个实例时计数放在 Redis 里，所有实例共用。

代码：`backend/src/security.ts`。
